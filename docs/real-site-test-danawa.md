# 다나와 소규모 실사이트 테스트 결과

로컬 서버와 모킹으로만 검증했던 크롤러를 실제 사이트(다나와)에서 소규모로 돌려 본 기록입니다. 이슈 #39.

## 조건

- 대상: `www.danawa.com`(robots.txt, 홈페이지 분석), `shop.danawa.com`(조립PC), 링크로 따라간 `pc26.danawa.com`
- 안전 조건: 시작 전 robots.txt 확인, `--delay 2`, `--max-pages 8`, `--max-depth 1`, 한 번에 한 세션, 차단(403 등) 시 즉시 중단
- 총 요청: 1~2차 17회(리다이렉트 제외), 3차 추가 8회. 홈페이지 2(분석용으로 한 번, 저장용으로 한 번), robots.txt 4(www 1, shop 2, pc26 1), 페이지 11(1차 3 + 2차 8). 실행마다 robots.txt 캐시를 새로 만들어 shop은 2번 요청했습니다. 홈페이지 2회와 robots.txt는 이 세션의 실행 기록 기준이며 크롤러 로그로는 페이지 요청만 셀 수 있습니다.
- 수집한 본문은 저장소에 커밋하지 않았습니다(저작권, 이용 약관). 아래에는 URL, 제목, 집계만 있습니다.

## 실행 결과

| 회차 | 크롤러 UA | 대상 | 결과 |
|------|-----------|------|------|
| 1차 | `python-requests` 기본값 | `shop.danawa.com` 시드 3개 | robots.txt 포함 전부 **403**, 수집 0, 건너뜀 3. 안전 조건에 따라 즉시 중단 |
| 2차 | `web-crawler-toy/0.1 (learning project)` | 같은 시드 3개, 깊이 1, 최대 8페이지 | **수집 8**, 건너뜀 725(723건은 깊이 초과), 중복 0, 10.6초 |

1차와 2차 사이에 의도적으로 바꾼 것은 User-Agent(PR #43)와 robots.txt 매칭(PR #41)입니다. 시각, 세션, IP는 통제하지 않았습니다. 식별 가능한 UA로 보낸 `www.danawa.com` 요청은 처음부터 200이었습니다(이 세션의 실행 출력 기준). UA가 403의 원인이었을 수 있지만, 각 조건에서 요청이 1회씩뿐이라 확정할 수 없습니다. 위장 UA나 차단 우회는 시도하지 않았습니다.

## 3차 실행: 카테고리 도달과 상품 추출

**카테고리 목록 URL을 얻은 경로.** 홈페이지의 카테고리 메뉴는 자바스크립트로 그려지지만, `robots.txt`가 `Sitemap: https://www.danawa.com/sitemap.xml`을 알려주고, 그 사이트맵에 있는 사람용 사이트맵 페이지 `https://www.danawa.com/info/map.html`에 `prod.danawa.com/list/?cate=…` 링크 124개가 정적 HTML로 들어 있습니다. 노트북(`cate=112758`), 브랜드PC/조립PC(`cate=112756`), 컴퓨터 BEST(`cate=11241973`) 등이 여기 있습니다. 다나와의 경우 브라우저 자동화 없이 카테고리에 도달할 수 있고, 목록 페이지는 상품을 서버에서 렌더링합니다. `robots.txt`의 `Sitemap:` 줄과 요청 횟수는 이 세션의 실행 기록 기준이며 저장된 파일로는 확인하지 못했습니다. 아래 표의 "제목"은 페이지의 `<title>`이라 사이트맵의 링크 텍스트와 다릅니다(`cate=112756`은 사이트맵에서는 "브랜드PC/조립PC", 페이지 제목은 "데스크탑 전체").

**조건.** 시드 3개(`--extract danawa --max-depth 1 --max-pages 3 --delay 2`), 식별 UA, `prod.danawa.com/robots.txt` 허용 확인. 요청 8회(리다이렉트 제외): 사이트맵 XML 1, 사이트맵 페이지 1, prod robots.txt 2(수동 확인 1, 크롤러 1), 목록 페이지 수동 저장 1(분석용), 크롤러 실행에서 목록 페이지 3. 컴퓨터 BEST 시드는 리다이렉트되어 크롤러가 리다이렉트 대상을 1회 더 요청했습니다.

**결과.** 수집 3, 건너뜀 2(목록끼리 서로 링크해서 이미 방문한 URL), 중복 0, 범위 밖 링크 174, **추출한 상품 278**, 8.8초.

| 목록 | 제목 | 추출한 상품(옵션 행) | 고유 상품명 | 가격 범위 |
|------|------|------|------|------|
| `cate=112758` | 노트북 전체 | 106 | 30 | 877,000 ~ 5,300,000원 |
| `cate=112756` | 데스크탑 전체 | 68 | 30 | 536,630 ~ 4,611,400원 |
| `cate=11241973` → `11256563`로 리다이렉트 | 2026 핫이슈 | 104 | 30 | 111,200 ~ 10,999,000원 |

- 목록 페이지마다 상품 카드 30개가 옵션(예: SSD 256GB, 512GB)별로 펼쳐져 68~106개 상품 행이 됩니다. 이름이 빈 상품과 가격 0 이하는 없었습니다.
- 노트북 목록 페이지를 저장해 분석한 결과 카드 45개 중 30개가 상품이고 15개는 내용 없는 스켈레톤이었습니다. 광고 링크(`loadingBridgeAdSmart.php`)는 `pcode`가 없어 제외했습니다.
- 페이지 사이에서는 같은 상품이 겹칩니다(노트북과 핫이슈 목록 사이 pcode 중복 61건). 추출기는 페이지 단위로 중복을 제거합니다.
- 수집한 상품 데이터는 저장소에 넣지 않았습니다.

## 테스트로 발견해서 고친 결함

| 결함 | 원인 | 수정 |
|------|------|------|
| robots.txt 와일드카드(`Disallow: /*?iframe=*`)를 처리하지 못해 금지 URL을 허용으로 판정 | 표준 라이브러리 `RobotFileParser`가 `*`, `$`를 지원하지 않음 | 이슈 #40 / PR #41: RFC 9309 방식 매칭 직접 구현 |
| 크롤러가 신원을 밝히지 않음 | `requests` 기본 UA 사용 | 이슈 #42 / PR #43: `user_agent` 설정과 `--user-agent` 옵션 |

## 남은 한계와 새로 알게 된 한계

1. **(해결됨, 위 3차 실행) 홈페이지에서는 컴퓨터/노트북 카테고리 목록에 도달하지 못합니다.** 홈페이지의 카테고리 메뉴는 자바스크립트로 그려져서(`CategoryLnb().setListRootUrl(...)`) 정적 HTML에 메뉴 링크가 없고, `prod.danawa.com/list` 링크는 JS 문자열 안의 배너 1건뿐입니다. 1~2차 실행에서는 그래서 서버가 HTML로 내려주는 조립PC(`shop.danawa.com`) 페이지만 수집했습니다. 3차 실행에서 robots.txt가 알려주는 사이트맵 경로(`/info/map.html`)로 카테고리 목록 URL을 얻어 노트북, 데스크탑 목록에 도달했습니다. 이 우회는 다나와의 사이트맵 구성에 기댄 것이라 다른 사이트에는 통하지 않을 수 있습니다.
2. **(수정됨, PR #50) 도메인 범위 제한이 없습니다.** 링크를 따라가다 `pc26.danawa.com` 같은 다른 서브도메인까지 수집했고, 깊이가 더 허용됐다면 `enuri.com` 같은 외부 사이트도 대상이 되었을 것입니다. 시드 도메인으로 제한하는 옵션이 필요합니다.
3. **(수정됨, PR #48) 최대 깊이에서 링크가 전부 "건너뜀"으로 집계됩니다.** 2차 실행의 건너뜀 725건 중 723건이 깊이 초과였고, 그만큼 WARNING 로그가 쏟아졌습니다. `.kiro/specs/web-crawler-toy/requirements.md`의 8.2(깊이 초과 거부)와 10.6(건너뜀 합산) 문구대로 동작한 결과이지만, 요약 통계와 로그의 신호 대비 잡음이 나쁩니다. 최대 깊이 페이지에서는 링크를 아예 큐에 넣지 않는 방식이 낫습니다(요구사항 수정 필요).
4. **(부분 해결, PR #56) 본문에 사이트 공통 메뉴와 다른 상품 정보가 섞입니다.** `<nav>`, `<footer>` 태그만 제거하므로 `div`로 만든 메뉴, 실시간 견적 목록, 다른 상품의 가격이 `body_text`에 그대로 들어옵니다. 상품 페이지 2개에서 콤마 숫자로 된 가격 표기가 각각 394건, 427건 잡혔지만 상당수는 그 상품의 가격이 아닙니다. `--extract danawa`가 목록 페이지의 상품을 이름, 옵션, 가격으로 구조화해 `products`에 담아 주므로 상품 데이터는 얻을 수 있지만, `body_text` 자체는 여전히 메뉴와 다른 상품의 가격이 섞인 그대로입니다. 상품 상세 페이지용 추출기는 없습니다.
5. **(수정됨, PR #46) robots.txt가 403이어도 "전부 허용"으로 처리합니다**(요구사항 4.4의 "실패하면 전체 허용"). 1차 실행에서 robots.txt와 모든 페이지가 403이었던 것처럼, 이는 허용이 아니라 차단 신호일 수 있습니다.

6. **페이지네이션을 따라가지 않습니다.** 목록 페이지 하나에서 상품 카드 30개만 얻습니다. 다음 페이지는 자바스크립트로 이동하는 것으로 보이며 이번에 확인하지 않았습니다.
7. **추출기는 저장해 분석한 노트북 목록 페이지의 구조에 맞춘 것입니다.** 데스크탑과 핫이슈 목록에서도 동작했지만 다른 카테고리와 상품 상세 페이지는 시험하지 않았고, 사이트가 카드 클래스나 aria-label을 바꾸면 추출이 실패합니다(이때는 로그를 남기고 상품 없이 페이지를 저장합니다).
8. **페이지 간 같은 상품 중복을 제거하지 않습니다.** 추출은 페이지 단위이므로 같은 상품이 여러 목록에 나오면 각각 저장됩니다.

## 추출기의 알려진 한계

검증 에이전트가 일부러 만든 HTML로 시험해 확인한 동작입니다. 예외는 없고 조용히 누락되거나 첫 값이 유지되는 경우이며, 이번에 실제로 받은 3개 페이지에서는 나타나지 않았습니다.

- 같은 카드 안에 이름 앵커(`… 상세보기`)가 여러 개면 첫 번째만 씁니다.
- 같은 `pcode`가 다른 카드에 나오면 먼저 나온 것이 유지되고 나중 것의 이름과 가격은 버려집니다.
- 카드가 중첩되면 바깥 카드가 안쪽 카드의 앵커를 자기 이름으로 가져갈 수 있습니다.
- 가격은 `1,000원`처럼 쉼표가 있는 형식만 인식합니다. 쉼표 없는 가격(1,000원 미만), `~`가 붙은 최저가 표기, `₩`·전각 숫자 표기는 행이 누락되거나(`₩1,000원`은 옵션이 `₩`로 들어감) 옵션에 잔여 문구가 남습니다.
- 가격이 0이거나 매우 큰 값이어도 걸러내지 않습니다.
- 추출이 예외로 실패하면 로그를 남기고 상품 없이 페이지를 저장하지만, 요약 통계에는 실패 수가 없어 "상품 0개"와 "추출 실패"를 요약만으로는 구분할 수 없습니다.

## 재현

```bash
.venv/bin/python -m web_crawler \
  "https://shop.danawa.com/shopmain/?logger_kw=dnw_gnb_pcmain" \
  --max-depth 1 --max-pages 8 --delay 2 --output result.jsonl -v

# 상품 추출 (카테고리 목록 URL은 https://www.danawa.com/info/map.html 에 있음)
.venv/bin/python -m web_crawler "https://prod.danawa.com/list/?cate=112758" \
  --extract danawa --max-pages 1 --delay 2 --output notebooks.jsonl
```

실제 사이트를 대상으로 할 때는 대상의 이용 약관과 robots.txt를 먼저 확인하고, 작은 값으로 시작하세요. 403, 429 같은 응답이 나오면 멈추고 재시도하거나 우회하지 마세요.
